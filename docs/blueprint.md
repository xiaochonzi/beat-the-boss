# Project Blueprint

## 背景与目标

将现有《今天又想打老板》浏览器 3D 游戏重构为真正支持 iOS 16+ 与 Android 11+ 的竖屏移动端 App，保留完整卡通物理解压玩法，优先验证 Flutter 3D，并为后续最小商业化能力提供清晰边界。

## 非目标

- 不将纯 WebView 或网页壳作为最终产品形态。
- 不把游戏核心建立为必须联网的服务。
- 不实现账号、云端存档或跨设备同步。
- 不在本 Blueprint 中锁定具体 Flutter 3D 库、原生渲染实现或备选引擎。
- 不使用血液、真实伤口、死亡、击杀或写实痛苦表现。
- 不在游戏核心模块中直接实现广告、统计、分享和去广告内购。
- 不设计复杂商城、在线排行榜或社交关系系统。
- 不在 Blueprint 中定义文件级实现路径、单功能验收用例或交付顺序。

## 用户与核心场景

- **主要用户**：工作间隙、午休或下班后需要快速解压的上班族。
- **进入游戏**：用户输入老板名字，系统生成固定 Seed 外观并进入竖屏办公室场景。
- **持续互动**：用户通过点击、长按、拖拽、甩动和投掷道具与老板及办公室发生物理互动；普通游玩不设时间上限。
- **完成一局**：解压值达到 100% 后进入 10 秒暴走模式，暴走结束自动结算；App 被切后台时自动暂停，回来后由用户点击继续。

## 成功标准

- iOS 16+ 和 Android 11+ 真机均能安装、启动并完成完整游戏流程。
- 主流中高端 iPhone 与 Android 设备达到稳定 60 FPS 的体验目标；中低端设备保持约 30 FPS 的可玩体验。
- 竖屏下，手势优先操作能够可靠完成点击攻击、长按蓄力、松手释放、老板拖拽甩动以及双指相机操作。
- 8 种道具、老板受击/倒地/恢复、物理碰撞/连锁反应、解压值、Combo、破坏度和暴走模式均可使用。
- 游戏核心在无网络状态下仍可完整游玩和结算。
- 设置、成就、最高 Combo、老板历史和游戏统计能够正确本地保存并在重启后恢复。
- 命中、强力攻击、倒地、连锁碰撞和暴走等关键事件具有一致的视觉、音频和触觉反馈。
- App 前后台切换、锁屏和系统中断不会导致游戏崩溃、输入失效或状态异常。
- Flutter 3D 技术验证失败时，可以在不改变产品能力边界的情况下替换为 Godot 或 Unity。

## 系统能力地图

- **移动端应用壳与生命周期**：启动、导航、竖屏布局、安全区域、后台暂停与恢复、退出和引擎生命周期。
- **游戏运行时核心**：游戏会话、场景状态、道具选择、攻击流程、结算和暴走流程编排。
- **3D 场景与物理交互**：程序化几何体、材质、灯光、相机、老板、办公室刚体、拖拽、投掷、碰撞和连锁反应。
- **游戏状态、进度与本地数据**：老板 Seed、运行统计、Combo、解压值、成就、设置、历史记录和本地数据迁移。
- **多感官反馈与设备能力**：卡通音频、老板对白、粒子、飘字、镜头震动、触觉反馈和画质档位。
- **最小商业化与平台服务**：广告、统计、分享、去广告内购、购买恢复、隐私授权和商业化降级；与游戏核心隔离。

## 模块与职责边界

### 应用壳与生命周期模块

- **职责**：管理 App 启动、页面导航、竖屏和系统生命周期，并协调游戏引擎的创建、暂停、恢复和销毁。
- **对外接口**：提供页面导航事件、前后台生命周期事件、暂停/继续命令和系统能力请求。
- **数据所有权**：拥有当前页面状态、系统生命周期状态和应用级显示配置；不拥有游戏规则或商业化数据。
- **失败边界**：导航或生命周期处理失败可能阻塞页面切换，但不应修改已保存的游戏统计；原生设备能力不可用时应允许核心游戏继续运行。

### 游戏运行时核心模块

- **职责**：编排一局游戏的开始、进行、暂停、暴走和结算流程，协调输入、场景、规则、反馈和持久化。
- **对外接口**：接收用户手势和道具命令，发布命中、碰撞、统计变更、对白、暴走、暂停和结算事件。
- **数据所有权**：拥有当前游戏会话的临时状态，包括当前老板、当前道具、会话进度和结算快照；不直接拥有持久化文件。
- **失败边界**：单局运行时失败应结束或暂停当前会话，但不应损坏历史成就、设置和既有统计数据。

### 3D 场景与物理交互模块

- **职责**：维护 3D 场景、程序化模型、相机、刚体、射线命中、老板拖拽、道具物理行为和碰撞事件。
- **对外接口**：提供场景初始化/销毁、输入命中查询、道具动作、相机控制和物理事件流。
- **数据所有权**：拥有场景对象、刚体、碰撞过滤、临时物体和渲染状态；不直接写解压值、Combo 或成就记录。
- **失败边界**：渲染或物理降级时可以降低画质、粒子或对象数量；如果物理不可用，应阻止错误的规则计分，不伪造有效命中。

### 游戏规则与反馈编排模块

- **职责**：根据命中和碰撞事件计算解压值、Combo、破坏度、道具统计、暴走触发和结算结果，并发出反馈事件。
- **对外接口**：接收物理事件和游戏动作结果，输出规则状态快照、反馈事件和成就触发事件。
- **数据所有权**：拥有当前会话规则状态和统计计算结果；持久化模块只接收其快照并负责保存。
- **失败边界**：反馈服务不可用不应阻塞规则计算；规则计算失败不得直接覆盖有效的本地历史数据。

### 游戏状态与本地数据模块

- **职责**：管理老板历史、Seed 相关记录、设置、成就、最高 Combo 和游戏统计的本地读取、保存、版本迁移与损坏恢复。
- **对外接口**：提供加载快照、保存会话结果、更新设置、读取历史和重置本地数据的能力。
- **数据所有权**：拥有所有本地持久化数据的生命周期、格式版本和写入权限。
- **失败边界**：数据读取失败时返回安全默认值并提示恢复；单次保存失败不得让游戏核心崩溃，也不得删除原有有效数据。

### 多感官反馈与设备能力模块

- **职责**：将规则和场景事件转换为音频、粒子、飘字、镜头震动和触觉反馈，并根据设备能力进行降级。
- **对外接口**：接收统一反馈事件，提供音量、震动、粒子和画质设置。
- **数据所有权**：拥有反馈资源、播放状态和设备反馈开关；设置的持久化由本地数据模块负责。
- **失败边界**：音频、触觉或粒子不可用时只降级对应反馈，不影响游戏输入、物理和规则状态。

### 最小商业化与平台服务模块

- **职责**：隔离处理广告、统计、分享、去广告内购、购买恢复、隐私授权和商业化联网状态。
- **对外接口**：接收游戏事件用于统计，读取结算快照用于分享，向游戏壳提供广告状态和购买状态。
- **数据所有权**：拥有商业化配置、购买状态缓存和统计发送队列；不拥有游戏核心存档、物理状态或规则数据。
- **失败边界**：广告、统计、分享或支付服务不可用时，核心离线游戏仍可启动、游玩和结算；购买状态不确定时不得错误地永久标记为已购买。

## 核心数据流

### 开始并进行一局游戏

```text
用户输入老板名字
  → 应用壳校验并启动游戏运行时
  → 本地数据模块读取历史与设置
  → 游戏运行时创建会话
  → 3D 场景模块按 Seed 创建老板与办公室
  → 反馈模块播放开始反馈
  → 用户手势驱动道具/拖拽
  → 3D 场景与物理模块产生命中和碰撞事件
  → 游戏规则模块更新解压值、Combo、破坏度和统计
  → 反馈模块输出音频、粒子、震动和 UI 反馈
```

### 暴走与结算

```text
规则模块发现解压值达到 100%
  → 游戏运行时进入 10 秒暴走状态
  → 规则事件通知场景、反馈和 UI
  → 暴走计时结束
  → 生成结算快照
  → 本地数据模块保存统计、最高 Combo、历史老板和成就
  → 应用壳切换到结算页
  → 商业化模块可读取结算快照执行分享/广告/统计
```

### 后台暂停与恢复

```text
系统生命周期事件
  → 应用壳通知游戏运行时暂停
  → 游戏运行时停止输入、规则计时、渲染推进和物理步进
  → App 恢复
  → 应用壳显示暂停状态
  → 用户点击继续
  → 游戏运行时恢复场景、物理、计时和反馈
```

## 外部系统边界

- **iOS / Android 生命周期**：提供前后台、锁屏、系统中断、屏幕方向和返回行为；由应用壳适配，不暴露给游戏规则模块。
- **GPU / Flutter 3D 渲染能力**：提供程序化几何体、材质、灯光、粒子和相机渲染；具体库保持可替换。
- **物理引擎**：提供刚体、碰撞、冲量、射线和动态对象能力；物理事件必须通过游戏运行时进入规则层。
- **本地存储**：提供离线数据保存；本地数据模块是唯一写入方。
- **音频与触觉设备**：提供音频播放和震动反馈；设备能力不可用时允许静默降级。
- **广告与统计平台**：属于商业化模块边界，可能需要网络和隐私授权；不可阻塞游戏核心。
- **App Store / Google Play 平台服务**：提供应用分发、内购验证和平台合规约束；不作为游戏规则数据源。
- **系统分享能力**：接收结算快照生成分享内容；分享失败不得影响结算和本地保存。

## 数据权威

- **当前游戏会话**：游戏运行时是唯一权威；场景和 UI 只读或通过事件更新。
- **物理世界状态**：3D 场景与物理交互模块是唯一权威；规则模块只消费规范化物理事件。
- **解压值、Combo、破坏度与本局统计**：游戏规则与反馈编排模块是唯一权威。
- **老板 Seed 与老板历史**：游戏状态与本地数据模块是持久化权威；老板生成模块只根据输入和 Seed 读取。
- **成就解锁状态**：本地数据模块是持久化权威；规则模块只能发出解锁意图。
- **设置**：本地数据模块是持久化权威；渲染、音频、触觉和游戏运行时只读取生效配置。
- **最高 Combo**：本地数据模块保存历史最大值；游戏规则模块提供本局候选值。
- **购买状态**：最小商业化模块是商业化状态权威；游戏核心只读取是否去广告这一只读结果。
- **分享内容**：以游戏结算快照为输入，不允许商业化模块反向修改游戏结果。

## 跨模块约束

- 游戏核心不得依赖网络、广告、统计、分享或支付服务才能启动和游玩。
- 3D 场景模块不得直接修改解压值、Combo、成就或本地存档。
- UI 不得直接操作物理世界或直接写持久化数据，必须通过游戏运行时和状态模块的公开接口。
- 本地持久化数据只能由游戏状态与本地数据模块写入，其他模块只提交快照或读取数据。
- 商业化模块不得成为游戏规则、物理状态或结算结果的数据权威。
- 所有跨模块交互优先使用明确的命令、状态快照或事件，不共享可变内部对象。
- App 暂停时必须同时停止游戏规则计时和物理推进，恢复前不得产生后台期间的命中或 Combo。
- 画质降级只能影响渲染和反馈质量，不得改变道具规则、物理事件语义或得分计算。
- 所有攻击、碰撞和成就事件必须可重复记录，便于本地统计、调试和后续商业化采集。
- 任何面向用户的反馈必须符合卡通、无血腥、无死亡、无写实伤害边界。

## 非功能要求

- **平台**：iOS 16+、Android 11+；首版同时支持两个平台。
- **方向**：竖屏为主，关键 UI 和手势区域适配安全区域。
- **性能**：主流中高端设备目标稳定 60 FPS；中低端设备目标约 30 FPS 可玩。
- **物理规模**：技术验证目标支持约 30～60 个动态物理对象。
- **可靠性**：前后台切换、锁屏和系统中断后不得出现明显崩溃、黑屏、触摸失效或状态损坏。
- **离线性**：游戏启动、核心操作、结算和本地历史读取不要求网络。
- **可维护性**：Flutter 3D 具体实现必须可替换；渲染、物理、规则和 UI 不应形成不可拆分的强耦合。
- **性能降级**：粒子、阴影、画质和动态对象数量应支持分级降级；降级不能破坏核心可玩性。
- **数据可靠性**：本地保存失败需安全处理；数据格式需要支持未来版本迁移和默认值恢复。
- **内容安全**：所有视觉、音频和文字反馈保持卡通、荒诞、非写实伤害表现。

## 风险与假设

- **风险**：Flutter 3D 生态仍可能存在 API 不稳定、平台兼容性和真机性能问题。
- **风险**：Flutter GPU、Impeller、Android Vulkan 驱动和不同厂商 GPU 可能造成渲染差异。
- **风险**：程序化几何体在提升材质、灯光和动画后，可能超过移动端性能预算。
- **风险**：老板拖拽、物理碰撞和连锁反应同时存在时，输入与物理事件可能产生歧义或不稳定。
- **风险**：移动端单指手势需要区分攻击、瞄准、老板抓取和道具栏操作。
- **风险**：广告、统计、分享和内购涉及平台审核、隐私授权和网络不可用场景。
- **假设**：首版不需要账号、云端数据或跨设备同步。
- **假设**：程序化几何体可以满足升级后的卡通视觉目标，不需要核心外部模型资源。
- **假设**：通过真实 iOS 与 Android 中高端设备测试，而不是只依赖模拟器，即可判断 Flutter 3D 是否达到技术门槛。
- **假设**：最小商业化模块可以通过事件和结算快照接入，而不需要侵入游戏规则。

## 未决问题

- Flutter 3D 最终采用哪一个具体引擎、渲染后端和物理后端。
- Flutter 3D 技术验证使用哪些具体 iPhone 和 Android 机型作为代表设备。
- 60 FPS 的统计窗口、允许的帧率波动、温度和内存上限如何定义。
- 最终程序化模型的细节等级、材质模型、灯光方案和动画表现标准。
- 动态物理对象的正式上限、睡眠策略和连锁碰撞的规则边界。
- 竖屏下单指手势冲突时的优先级和取消规则。
- 本地数据的具体格式、历史老板数量上限、数据损坏恢复交互和重置入口。
- 音频资源形式、老板对白是否为预录语音，以及触觉反馈在不同平台的强度映射。
- 广告形式、统计平台、分享渠道、去广告商品价格、购买恢复和隐私授权流程。
- 是否需要为商业化保留匿名设备标识或账号能力；该问题属于 Brief 2 后续 Spec。
